# A Hybrid Beam Search Framework with Deep Representation Learning for the Multiple Longest Common Subsequence Problem

## Overview

This project provides a framework for solving the Multiple Longest Common Subsequence (MLCS) problem using a hybrid beam search approach. By integrating deep representation learning with heuristic search, the framework leverages a lightweight Transformer encoder to capture local contextual features. This addresses the limitations of existing approximation methods in processing large-scale biological sequences, effectively balancing computational efficiency with solution quality.

The analysis workflow consists of the following stages:
1. **Data Preprocessing and Model Training**:
   - Slicing DNA sequences using a sliding window mechanism.
   - Training a lightweight Transformer encoder via contrastive learning (Triplet Loss) to learn semantic embedding vectors for sequence fragments.
2. **Hybrid Beam Search Execution**:
   - **Non-dominated Filtering**: Performing preliminary screening of search branches to eliminate invalid states.
   - **Dual-bound Evaluation**: Assessing candidate paths using an improved heuristic upper bound (theoretical potential) and a structural lower bound (alignment compactness).
   - **Multi-dimensional Scoring and Pruning**: Integrating representation-based priority with dual-bound information to retain Top-K high-potential paths.

## Source code

The source code is provided in the `code/` directory.

- `code/representation_guided_mlcs_search.py`: implementation of the proposed representation-guided hybrid beam search framework for the MLCS problem. This script includes Transformer-based sequence-fragment representation learning, embedding precomputation, non-dominated filtering, dual-bound evaluation, multidimensional scoring, and beam pruning.
- `code/upper_bound_baseline_search.py`: implementation of the upper-bound-only baseline used for ablation comparison.
- `code/parameter_sensitivity.py`: script for the parameter sensitivity analysis of beam width and sliding-window size.

The scripts are provided to support editorial and peer review of the manuscript and to facilitate reproducibility of the reported experiments.

## Configuration files

The `configs/` directory provides structured experimental settings corresponding to the main method, baseline comparison, sensitivity analysis, and dataset construction.

- `configs/default.json`: default configuration for the proposed representation-guided hybrid beam search framework.
- `configs/ub_baseline.json`: configuration for the upper-bound-only baseline.
- `configs/sensitivity.json`: parameter grid for beam width and sliding-window size sensitivity analysis.
- `configs/dataset_settings.json`: dataset construction settings for simulated and real biological experiments.

These configuration files are provided to make the experimental settings transparent and easier to reproduce.

## Dataset Description

The datasets are organized into `random-data/` and `real-data/` folders, with all sequences provided in standard `.fasta` format.

### 1. Simulated Datasets (`random-data/`)
These are generated by randomly sampling nucleotides to evaluate performance variations across different scales.
* **`random-data/length/`**: The number of sequences is fixed at 50, with lengths varying from 300 to 800.
* **`random-data/number/`**: The sequence length is fixed at 1000, with the number of sequences varying from 15 to 75.

### 2. Real Biological Datasets (`real-data/`)
Sourced from the NCBI public database, these include complete genome sequences of bacteriophages infecting opportunistic pathogens such as *Escherichia*, *Klebsiella*, and *Hafnia*.
* **`real-data/length/`**: Used to verify effectiveness under real biological constraints like uneven base distributions and local variations.
* **`real-data/number/`**: Used to test stability and robustness under high-dimensional constraints.

## Original data sources for real biological datasets

The real biological datasets used in this study were derived from complete bacteriophage genome sequences originally obtained from the NCBI Nucleotide/RefSeq database. The FASTA files in `real-data/` were generated by sequentially truncating fragments of the required lengths from these source sequences according to the experimental settings described in the manuscript.

The real-data benchmark files were generated in a nested manner. For the varying-sequence-number experiments, `1000×N` denotes sequence length 1000 with `N` sequences, where `N ∈ {15, 25, 35, 45, 55, 65, 75}`. Each `1000×N` subset uses the first `N` accessions in the ordered list below. For the varying-sequence-length experiments, `50×L` denotes 50 sequences with sequence length `L`, where `L ∈ {300, 400, 500, 600, 700, 800}`. Each `50×L` subset uses the first 50 accessions in the ordered list below. Therefore, the last column reports the benchmark subsets in which each accession is included, rather than a single evidence file.

In the repository, the varying-sequence-number FASTA files are stored under `real-data/length/` as `1000×N_group1.fasta`, and the varying-sequence-length FASTA files are stored under `real-data/number/` as `50×L_group1.fasta`.
